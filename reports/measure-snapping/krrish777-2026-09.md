# Summary of Activities – Measure Snapping – September 2026

Grant proposal: https://github.com/FreeCAD/FPA-grant-proposals/issues/91

This report covers stage 1 (PR 1), worked on from July to September 2026.

## Stage 1 Implemented

The work planned for PR 1 (distance snapping, hover preview and the backward-compatibility tests) is implemented and in review.

Each side of a Distance measurement now has its own snap mode, Snap1 and Snap2: Auto, None, Vertex, Center, Midpoint and Axis.
This makes rim-to-rim clearance, midpoint-to-center and axis-to-axis measurements possible without creating reference geometry.
The mode is stored on the measurement, so it stays parametric and recomputes correctly.
While hovering, the tool shows a marker at the point it will snap to, or a dashed line for cylinder and cone axes.
The markers are hidden for measurement types that do not use snapping, like Area.
The snap mode for each element can also be chosen directly in the task panel (in #31149).

As promised in the proposal, the regression tests for the existing distance results were written first, before any snapping logic.
The snapping core adds 102 unit tests in total.

## Challenges

- **Hover preview rendering.** This was the main risk in the proposal. As planned, I started with a small throwaway prototype to check how the Coin3D overlay behaves when views are closed, documents are switched and the app exits, before writing the real indicator. No crashes or leftover markers came up.
- **Measurements in assemblies.** During testing, markers and results were misplaced for geometry inside links and imported compounds. The cause was an existing bug in Part, where the internal location of a sub-shape was dropped. It is fixed separately in #31904.
- **Feedback from testing.** Testing on real models found several problems: hints misplaced in assemblies, no axis snap for circles, no angle between a cylinder axis and an edge, center-to-center not working on cylinders, and no way to pick the snap mode in the task panel. These are fixed. Some design questions from the same feedback, like how the hints should look and whether they stay visible after picking, still need input from the Design Working Group.
- **Review iterations.** #31909 went through three review rounds with Lokestrom, about when the markers should show, tolerance values and C++ style.

## Changes to the Plan

- Angle measurement for cylinder and cone axes was planned for PR 2 (deliverable 2). It was needed to fix the feedback above, so it was done early and is already merged in #31905.
- Picking the snap mode in the task panel came up in the feedback, so it is added now, ahead of the keyboard shortcuts planned for PR 2.
- **Behaviour change in Auto mode.** The proposal said existing files would give identical results, and this is not fully true anymore. To fix center-to-center on cylinders, Auto now measures axis to axis when both elements have an axis: cylinder or cone faces, straight edges that are parallel and apart, and a cylinder or cone with a circle. This follows the same idea as Quick Measure in the status bar. Before, these pairs were measured between the nearest points. Saved documents with these pairs can recompute to a different value, so I will point it out in the PR for the release notes. Setting the snap mode to None still gives the nearest-points result.
